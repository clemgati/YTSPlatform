# Engineering Principles

## Clarity over cleverness

Code should be easy to understand before it is clever.

---

## Shared first

Business logic belongs in shared code whenever practical.

---

## Design for evolution

Create boundaries that make change easier.

---

## Document decisions

Code explains how.

Documentation explains why.

---

## Small, focused changes

Every PR should solve one problem well.

---

## Build with intention

Every dependency, abstraction, and feature should earn its place.
